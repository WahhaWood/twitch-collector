# Twitch Collector

Панель прогресса дропсов и значков Twitch для нескольких знакомых. Вход по личному токену, до 5 Twitch-аккаунтов на человека.
Спека: `plan-mvp.md`, задачи: `Plan.md`.

## Как устроено
- Next.js 16 (App Router, cacheComponents) + Drizzle + Neon Postgres, хостинг Vercel Hobby.
- Аккаунт подключается через device code flow Twitch (код вводится на twitch.tv/activate). Токен шифруется AES-256-GCM.
- Прогресс и каталог берутся из неофициального GQL Twitch (`src/lib/drops.ts`). Дашборд дропсов Twitch закрыт проверкой клиента,
  поэтому кампании ищутся через live-стримы с включёнными дропсами (`channel.viewerDropCampaigns` отдаёт и личный прогресс),
  а полученные награды берутся из inventory. Кампания без live-стрима не находится, но уже найденные остаются с датой обновления.
  Всё непонятное получает статус `unknown`.
- Синхронизация: GitHub Actions раз в 15 минут дёргает `POST /api/internal/sync`; на странице аккаунта есть ручная кнопка «Обновить».
- Статистика (`/stats`): минуты просмотра по дням (прирост прогресса между синхронизациями, `progress_history`), полученные награды
  (`rewards`, из inventory Twitch, включая полученные до подключения), разбивка по играм и аккаунтам, кампании под угрозой, здоровье синхронизации.
  Дни считаются в часовом поясе браузера.
- «Что смотреть сейчас» на дашборде: забрать досмотренное → самые срочные выполнимые кампании с live-каналами (`live_channels`) →
  кампании, которым нужна привязка игрового аккаунта. Логика — чистые функции в `src/lib/stats.ts`.
- Автозабор: каждая синхронизация забирает досмотренные дропсы и значки (`claimDropRewards`); `claimed` ставится только по ответу Twitch.
- Воркер просмотра (`npm run worker`, постоянный процесс): на аккаунт до 2 каналов одновременно. Сначала стрики выбранных стримеров
  (`/streaks`, 7 минут за эфир), остальное — канал самой срочной кампании, если на `/accounts` включён «Автопросмотр дропсов».
  Просмотр: HEAD свежего HLS-чанка + spade `minute-watched` каждые 20 с; раз в 15 минут — sync с автозабором.
  Автопросмотр нарушает правила Twitch: возможны санкции к аккаунту.
- Админка (`/admin`, для `users.is_admin`): создание пользователей, перевыпуск токенов, удаление.

## Локально
```bash
npm ci
cp .env.example .env.local   # заполнить, ключ: openssl rand -base64 32
node --env-file=.env.local node_modules/.bin/drizzle-kit migrate
npm run user:create -- --name "Вася" --admin   # печатает токен входа один раз; --admin даёт доступ к /admin
npm run dev
npm run worker   # отдельный терминал: просмотр для дропсов и стриков, Ctrl+C — стоп
```
Проверки: `npm test && npm run typecheck && npm run lint && npm run build`.

## Деплой
1. Vercel: импортировать репозиторий, задать env из `.env.example` (`TWITCH_GQL_CLIENT_ID` можно не задавать).
2. Применить миграции к боевой базе (команда выше с боевым `DATABASE_URL`).
3. GitHub → Settings → Secrets → Actions: `APP_URL` (https://<app>.vercel.app без слэша на конце) и `CRON_SECRET` (тот же, что в Vercel).
4. Workflow `sync` можно запустить вручную (Run workflow) и проверить ответ 200.
5. Первого администратора создать скриптом с `--admin` (с боевым `DATABASE_URL`), остальных — на странице `/admin`.

## Fixture реального ответа
После подключения аккаунта: `npm run drops:dump -- --id <account id>` сохраняет `src/lib/__fixtures__/drops-sources.real.json`
и печатает сводку по статусам. По ней проверяем, что парсер понимает живые данные.
